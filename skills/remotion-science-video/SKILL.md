# remotion-science-video：配乐科普视频与小红书发布素材

把主题和用户提供的音乐做成可编辑、可预览、可导出的 Remotion 视频；成片交付时同步输出小红书视频封面与文案。复用这次制作方式，具体事实、主体数量、配色和时长随新主题确定。

## 输入与默认规格

先复用会话中已给出的主题、文件、风格认可和修改要求。继续修改已有工程时，直接进入相关步骤，不重新走整套试片流程。

| 输入 | 默认与处理 |
| --- | --- |
| 主题与范围 | 明确讲什么、包含哪些对象；缺少时一次简短询问 |
| 音乐 | 接收附件或本地路径，确认文件可读取及实际时长；没有音乐时先做资料和分镜，不虚构节拍 |
| 画幅 | **1920×1080、30fps、16:9横屏**；发布到小红书也保持此默认，用户要求竖屏再改 |
| 叙述 | **不配音**，中文标题、图表与字幕讲清知识点 |
| 风格 | 沿用已认可的风格；新项目可提出两个简短方向并推荐一个，不对已确认内容反复询问 |
| 时长 | 由信息量、音乐乐句和用户要求共同决定，不硬编码为某次作品的长度 |
| 制作阶段 | 默认先10秒试片、确认后分段推进；用户已明确批准整片制作或导出时，执行相应范围 |

需要原文、可直接复制的启动提示词或主题填写示例时，读 [原始四步与启动模板](references/four-step-prompt.md)。

## 成片输出约定

- 完整视频制作或整片导出任务，默认在当前视频项目的工作文件夹根目录生成实际可播放的 `主题.mp4`，同时生成 `主题_小红书竖版封面.png`、`主题_小红书横版封面.png` 和 `主题_小红书发布文案.md`；用户明确指定输出目录或文件名时按其要求执行。
- 工作文件夹指本次视频工程所在目录；多个工程并存时使用本次正在制作的工程，不将输出写入技能安装目录、全局缓存或其他项目。导出前确定绝对路径，渲染命令显式指定 MP4 输出位置。
- MP4、封面和文案作为同一套成片成果交付，无需用户另行提出生成发布素材。文案包含推荐标题、备选标题、可复制正文和标签；具体封面规格与文案组织按 [小红书发布指南](references/xiaohongshu.md) 执行。
- 封面与文案以最终导出的 MP4 为准；视频修改后同步检查并更新主题、数据、实际时长及介绍。交付前确认所有必需文件存在，检查视频可解码、封面可打开及中文显示正确、文案内容完整，并提供各文件的绝对路径或可点击链接。缺少任一成果时如实说明，不能宣称整套交付完成。
- 仅要求分镜、10秒试片或 Studio 预览时，交付相应阶段成果；首次试片仍等待风格确认。用户明确只要视频、不要封面或文案时按其范围执行。生成发布素材不代表获得上传或发布授权。

## 工作流

### 1. 设置主题，核查事实，建立分镜

- 检查现有 Remotion 工程与可用素材；新建或修改视频时，使用环境中可用的 Remotion 插件技能，按需读取创建、动画、预览、渲染指南。没有插件时依据项目安装版本的官方文档实现，不硬编码插件缓存路径。
- 确定科普主题后，先按下方“主题内容规划”检查各个方面，再根据受众、主题相关性、资料可信度和视频时长选择叙事主线；用户已限定内容范围时在其范围内规划，不强行扩展。
- 时效性数据从官方公告、年报或报告核实。记录主体、统计日期、单位、范围、原始数值和来源，资料放工程 `docs/`，不把案例旧数字当新事实。
- 集团装机、上市公司市值、控股与权益装机分别标清。母集团未整体上市时展示代表上市平台并写明主体；“未单列”“未披露”和0分别保留原始含义，不将表格里没有列出的数据默认为0。
- 正片保留理解图表必需的短口径与日期；详细限制、计算和来源进入资料文件。标题写知识点，避免“十一家同屏”“这里逐个出现”等制作说明。
- 列出场景、核心信息、动画方式和暂定节拍数；先保证主题对象覆盖完整，再调整重点，不用某一家示例替代整体对比。

#### 主题内容规划

| 考虑方面 | 需要回答的问题与呈现方式 |
| --- | --- |
| 运行原理 | 输入什么、经过哪些关键环节、如何产生输出或实现功能；用过程动画、结构剖面或能量/物料/信息流解释，并交代适用条件与主要限制。 |
| 中国国内现状 | 中国目前处于什么发展阶段，应用在哪里，规模、产能、产量、装机或渗透率如何，存在哪些瓶颈；区分已投运、在建、规划、示范和商业化，标明统计时间与范围。 |
| 关键技术与设备 | 哪些技术决定效率、成本、可靠性或规模化，分别依赖哪些核心设备、部件或材料；展示“原理环节 → 技术难点 → 对应设备”的联系，避免仅罗列名词。 |
| 设备关键供应商 | 谁供应上述设备、核心部件或材料，国内外代表企业分别覆盖哪个环节；核实具体产品、技术路线及供货或商业化证据，区分设备商、运营商、集成商、母集团与上市主体，不把概念关联写成确定供货关系。 |
| 相关市场变化 | 对应产品或服务的需求、市场规模、销量、价格、订单、竞争格局等如何变化；选择与主题最相关的指标，明确地域、单位、统计区间，区分历史实绩与预测，不混用产能、产量、营收和市场规模。 |
| 相关企业市值变化 | 选择有明确业务关联的上市公司，说明观察区间内市值如何变化；标注公司、代码、交易所、币种、估值口径及起止交易日，区分总市值、流通市值、股价与收益率，不将母集团、单一上市平台或同一公司多地上市市值混为一谈。 |

- 准备阶段给出简短内容提纲，注明各方面“纳入、简述、不适用或待核查”、核心结论、拟用图示与来源；不要求六个方面等长或各占独立一章。没有相关市场、上市主体或可靠数据时如实说明，不强行加入市值页。
- 可按“原理 → 国内进展 → 核心设备 → 供应商 → 市场与市值变化 → 收束”组织技术产业主题；企业比较主题可先给规模与结构总览，再解释关键差异。优先讲清一条因果或问题主线，沿革仅在有助理解时加入。
- 国内现状优先核查主管部门、统计机构和行业权威资料；技术与供货关系优先查论文、技术资料、招投标、公司年报及公告；行情优先查交易所或可追溯的市场数据。不同来源口径有差异时先统一或明确标注。
- 市场与市值趋势用相同口径的时间序列或起止对比表达；跨币种比较时注明汇率及日期。行情变化与技术突破、政策、订单等事件可并列展示，不能仅凭时间接近就断言因果；科普结论与投资判断分开，不据此编造目标价或收益承诺。

### 2. 分析上传音乐，把画面排到重音上

- 对实际文件分析每分钟节拍数（BPM）、瞬态、重音及乐句边界，输出秒数与帧号。估计节拍和听感强鼓击需区分；速度变化时使用分段或事件时间表。
- 按原始四步制作时，切场、图表逐项入场和沿革节点都安排在经核查的重拍。用户已要求紧凑逐项动画的项目，轻量逐行入场可采用普通拍或半拍，重大切场和关键节点仍优先使用强鼓击；用户明确要求所有入场都在重拍时按严格模式执行。连续缓动在拍位之间完成。
- **默认从源音乐起点连续播放，到精简后画面的合适乐句末收尾。**整片只有一条背景音乐时间轴，不在章节或企业组件内重启、循环，不为拼上原曲尾奏跳过中段。
- 用音乐节拍决定场景长度，再检查全片结束是否自然。结尾先选乐句边界，再做适量渐弱；用户要求整首音乐时按整首重新排画面。
- 新视频制作音轨、已有视频修复音乐或需要导出前核查时，读 [音乐与动画校验](references/music-and-motion.md)。

### 3. 用 Remotion 制作，关键动作配代码音效

- 动画由帧驱动，可在任意帧复现；企业、年份、图表数据和入场时刻配置化。画面时长与音乐取自同一总时间线。
- 规模和市值使用适合横向比较的条形图，结构使用分段条形图或占比图，辅以火电、水电、核电、风电、光伏等语义图标。颜色在同一套对象和类别中保持一致。
- 逐家、逐行浮现应清晰可见：整行标签与图条协同淡入或滑入，条形再展开；缩短总片长时压缩静止等待，保留独立入场过程。
- 各家发展史用一段完整的动态小场景呈现，以年份、关键事件和图标串联；通常精选2—3个节点。批量对象按相近乐句长度安排，内容多的对象合理加时。只有用户要求独立动图文件时才另导出 GIF 或动画 WebP。
- 过门可用“诞生 → 重组 → 转型”等叙事词，按拍逐词浮现并配对应元素。避免全部元素一开始就静止铺满。
- 为关键出现、合并、节点点亮等动作代码合成短音效，音色配合主题，低音量叠加在连续配乐上；音效不能盖住原曲鼓点。避免为每帧运动或无意义细节堆音效。

### 4. 先看10秒，再分段完善

- 默认先做开头约10秒的实际可播放预览，能判断视觉风格、字幕、图表入场和音乐卡点。通过 Remotion Studio 预览；用户需要试片文件时导出这一小段。
- 首次试片交付后等待用户确认风格，再按段推进。用户已确认或明确要求整片时延续授权，不重复请求确认同一内容。
- 反馈只重做相关片段，并校验受影响的音轨和相邻转场。记录最新有效要求，避免下一次导出恢复旧文案或旧音乐。

### 5. 细节优化与成片交付

- 文案一屏一个主结论，删除重复说明和长句；数字标签留必要单位与日期，画面不堆限制性备注。
- 用户要求更紧凑或可以暂停核查时，优先缩短总览、板块占比和图表完成后的静止时间；不要将动画本身加速到无法看出逐行浮现。
- “主力电源，各有不同”等解释页需有足够时间完成类别出现；沿革段按乐句统一节奏，不强求每段相同秒数。
- 检查条形颜色、截断文字、缺字方框、多余边框、虚线框、重叠与画面边缘。用稳定的中文字体和 SVG 图标，抽看首次、逐行中间、全部完成与切场前的帧。
- 用户要求“整体输出”“导出”“给MP4”时按“成片输出约定”导出到当前项目工作文件夹，完成参数、解码、关键帧、切场卡点、实际音轨连续性和结尾检查，并同步生成封面与文案后交付整套文件。只要求预览时保持Studio可用。
- 整体改动后检查头尾自然、各对象齐全、文案与数据一致；不能只凭编译通过宣称音乐、视觉均已通过。
- 仅在用户要求清理时删除明确被替代的旧成片；先确认最终版已验证，限定输出目录和文件清单，保留源音乐、源码、数据与仍需交付的动图。

### 6. 生成小红书发布包

每次完整成片交付时默认执行本步骤，读 [小红书发布指南](references/xiaohongshu.md)，同步生成与**最终成片**匹配的封面、标题、正文与标签；用户单独要求发布素材时也直接执行。遵循“成片输出约定”，不自动登录、上传或发布。

## 按当前阶段交付

- 准备阶段：主题内容提纲与各方面取舍、分镜、来源及实际音乐节拍时间表。
- 试片阶段：10秒预览链接或用户要求的试片文件，简短说明待确认的风格点。
- 成片阶段：工作文件夹中的完整MP4、横竖两版小红书封面与发布文案，同时提供可编辑工程、必要的来源与验证记录；独立GIF按需交付。
- 单独制作发布素材：竖版与横版封面、含推荐和备选标题、可复制正文与标签的文案文件。

只报告实际完成的检查；无法试听、源文件缺失或数据未披露时，明确具体缺口，不编造核验结果。
